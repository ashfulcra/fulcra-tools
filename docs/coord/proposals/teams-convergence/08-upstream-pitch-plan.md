## Contribution preparation

Prepare an independently reviewable branch and a compact evidence package:

1. Verify each skill works with the documented dependencies and public links.
2. Provide architecture and compatibility documentation that does not require
   access to a team's account, private files, or deployment history.
3. Run synthetic examples and tests; include exact commands and results.
4. Recheck upstream APIs and contribution conventions before opening a PR.
5. Scan the proposed publication for personal data and account identifiers.

## Review and sequencing

Discuss ownership and maintenance costs with upstream maintainers. Start with
additive skills; handle changes to existing conventions in separate proposals.
Follow the three-track design in [`07-upstream-plan.md`](07-upstream-plan.md).
Keep team-specific scheduling, approvals, and internal pitch notes outside the repo.
